You are designing the complete UI/UX for a real university software engineering project called: INTERNPRANGON "Smart Choices for Your First Steps" InternPrangon is an internship discovery and management platform designed primarily for university students and early-career users. IMPORTANT: This is a real software engineering project that will later be implemented as a MERN-stack web application. The Figma design will be the visual source of truth for the React frontend. Do NOT create a generic AI-generated SaaS dashboard. Do NOT design disconnected pages independently. Create a coherent product with a consistent visual identity, reusable components, clear information architecture, and realistic user flows. ================================================== PRODUCT GOAL ================================================== InternPrangon helps students: - discover internships - search and filter opportunities - save internships - apply using a saved resume - track applications - learn about companies - read anonymous company reviews - contribute stipend information - share interview experiences - earn contributor points and badges Companies/HR can: - create and manage company profiles - submit verification information - post internships after verification - manage internship listings - view applicants - download applicant resumes - update applicant application status Admins can: - verify companies - reject or remove fake companies - moderate reported reviews - monitor the platform ================================================== USER ROLES ================================================== Design three distinct but visually consistent experiences: 1. STUDENT 2. COMPANY / HR 3. ADMIN Each role should have its own navigation, dashboard information, actions, and workflows. Do not make the three dashboards identical with only different text. ================================================== CORE FEATURES ================================================== Student features: 1. Student profile management 2. Internship search by keyword 3. Internship filtering - Paid - Unpaid - Remote - Onsite 4. Internship details 5. Resume upload 6. One-click application 7. Saved internships 8. Application tracking 9. Anonymous company reviews 10. Star rating 11. Anonymous review comment 12. Stipend information 13. Interview experience archive 14. Contributor points 15. Contributor badges 16. Contributor leaderboard 17. Notifications 18. Internship deadline highlighting Company/HR features: 1. Company profile 2. Company verification submission 3. Verification status 4. Internship creation 5. Internship management 6. Applicant tracker 7. Resume download 8. Application status management Admin features: 1. Admin dashboard 2. Company verification 3. Approve company 4. Reject company 5. Delete fake company 6. Review moderation 7. Delete reported/fake review ================================================== DESIGN PHILOSOPHY ================================================== The product should feel: - professional - trustworthy - youthful - career-oriented - modern - approachable - polished - easy to use The student experience should feel encouraging and energetic. The company experience should feel professional and structured. The admin experience should feel efficient and information-focused. Maintain one unified InternPrangon brand across all three. ================================================== AVOID GENERIC AI DESIGN ================================================== Do NOT rely on: - generic blue SaaS dashboards - excessive gradients - excessive glassmorphism - random floating cards - excessive rounded containers - meaningless decorative graphics - generic stock illustrations - Lorem Ipsum - inconsistent typography - inconsistent spacing - unnecessary animations - visually impressive elements that reduce usability Every visual element should have a purpose. ================================================== DESIGN SYSTEM FIRST ================================================== Before designing all application screens, establish a reusable design system. Define: - brand colors - semantic colors - typography - font hierarchy - spacing - grid - border radius - shadows - icons - buttons - form fields - dropdowns - search bars - cards - tables - badges - ratings - avatars - navigation - sidebar - tabs - modals - dialogs - alerts - notifications - pagination - empty states - loading states - error states - success states Use reusable components and variants. ================================================== RESPONSIVE DESIGN ================================================== Design for: Desktop: 1440px Tablet: 768px Mobile: 390px Do not simply shrink desktop layouts. Design intentional responsive behavior. ================================================== REALISTIC CONTENT ================================================== Use realistic fictional internship and company data. Examples: Software Engineer Intern Frontend Developer Intern Data Analyst Intern UI/UX Designer Intern Marketing Intern Do not use real people's personal information. ================================================== ACCESSIBILITY ================================================== Prioritize: - readable typography - sufficient contrast - clear focus states - clear labels - appropriate button sizes - understandable error states - accessible navigation ================================================== FIGMA FILE ORGANIZATION ================================================== Organize the file professionally: 01 — Cover 02 — Design System 03 — Components 04 — Public 05 — Student 06 — Company HR 07 — Admin 08 — Responsive 09 — Prototype Use meaningful names for frames, components, variants, and sections. ================================================== IMPORTANT DEVELOPMENT CONSTRAINT ================================================== The final Figma design will be implemented in React and connected to an existing Node.js/Express/MongoDB backend. Therefore: - favor implementable layouts - use reusable components - avoid unnecessarily complex effects - maintain consistent component patterns - keep forms and data tables practical - design realistic states for API-driven data - account for loading, error, empty, and success states Figma should define the visual design. React will later implement the design. The existing backend API will provide the data. ================================================== WORKING METHOD ================================================== Do NOT immediately generate every screen. Work in stages. Stage 1: Brand and design system. Stage 2: Public and Student experience. Stage 3: Company / HR experience. Stage 4: Admin experience. Stage 5: Responsive layouts and prototype flows. Wait for design review between stages. The final product should feel like one professionally designed application rather than multiple AI-generated pages. The goal is a polished, production-quality UI/UX for InternPrangon that can realistically be implemented in a MERN-stack application.
